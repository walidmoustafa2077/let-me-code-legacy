Agent factory · opencode · MCP

One command turns a project into a working agent team.

let-me-code installs eleven specialised subagents, forty workflow skills, and a delegation MCP server into whatever repository you point it at. The orchestrator then routes work to the right specialist instead of asking one model to do everything. 

$ npx github:walidmoustafa2077/let-me-code

Node.js 22.18 or newer · opencode installed · MIT licensed · source on GitHub

How it works

A single orchestrator session owns the conversation. When a request needs real work, it writes tickets, hands each one to a scoped child agent, and reads back only the diff and the handoff — not another agent's whole transcript. Code, review, and commit stay separate so a reviewer can reject what an implementer produced.

  1. RouteClassify the request as a spike, a bounded ticket, or architecture, then pick the workflow.
  2. SpecifyArchitect turns intent into a spec and constraints; tickets are sliced until each is independently testable.
  3. ImplementSenior-dev builds a thin verifiable slice, leaving the tree dirty for review.
  4. ReviewQA runs the suite against the spec, scans for security issues, and flags over-engineering.
  5. LandGit-agent commits only what passed, with your review checkpoint in between.

The delegation server speaks to a warm opencode serve instance, detects v1 or v2, and supports per-agent model resolution with fallbacks so a stale provider name degrades instead of failing the job.

The roster

Eleven agents, each with a narrow job and its own permissions.

orchestrator
Owns the plan, delegates, reconciles the board.
architect
Turns intent into a spec, constraints, and gated tickets.
challenger
Attacks the plan before any code is written.
senior-dev
Implements tickets in thin, verifiable slices.
junior-dev
Scoped boilerplate and helpers under supervision.
qa-engineer
Tests the diff against the spec; scans for security issues.
git-agent
The only writer to git; commits verified work, never pushes.
tech-writer
Docs, ADRs, and retrospectives after a feature lands.
minimalism-enforcer
Flags over-engineering and demands the simplest version.
devobs
Audits Docker, CI pipelines, and deployment config.
visualizer
Fast UI mockups and accessible component templates.

Install

Run it inside the project you want the factory in. Existing files are backed up, never clobbered, and the MCP dependency install plus its test run are part of the bootstrap.

$ npx github:walidmoustafa2077/let-me-code

# then, in that project
$ opencode serve --port 4096   # terminal one
$ opencode                     # terminal two

Useful flags: --yes, --force, --no-install, --no-test, --no-git, --model <id>.

On opencode v2 export OPENCODE_SERVER_PASSWORD before starting the server and the client; the two sides negotiate auth on their own.
